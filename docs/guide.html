Project guide

DTE, in Plain Terms

A website that puts household energy costs next to DTE Energy’s finances. Every number has a source. If a number is missing, the page says so.

This guide is the short version. It explains what the site does, how to run it, and where to look in the code.

1. What the site is

The site is independent. DTE Energy did not publish it.

It has two kinds of numbers:

  • Checked numbers come from public agencies and from DTE’s own filings. They are saved in the project and shown on the main pages.
  • Uploads are spreadsheets anyone can add. The site describes them and compares them with the checked numbers. Uploads are marked “not checked.”

2. The pages

PageAddressWhat you see
Home/Four big numbers: energy burden, the price of electricity, shutoffs, and CEO pay.
Household/householdA neighborhood map, burden by income, shutoffs, and electricity prices.
Financials/financialsStock price, dividends, revenue growth, and CEO pay.

Your data/dataUpload a file, and see recent uploads.
Saved upload/data/…Charts and short findings for that file.

Energy burden means the share of a household’s income that goes to home energy. Above 6% is treated as high.

Two lines moving together does not prove that one caused the other. The Compare page says this in plain words.

3. Where the checked numbers come from

The site does not call those agencies every time someone opens a page. A script downloads the files once and saves one snapshot: src/server/data/verified.json.

TopicSource
Stock price, dividends, revenue growthSEC filings and Yahoo Finance
CEO payDTE proxy statements, typed into a JSON file
Customers, sales, prices, billsU.S. Energy Information Administration (Form EIA-861)
ShutoffsMichigan Public Service Commission case U-18120, typed into a JSON file
Energy burden and the mapU.S. Department of Energy, LEAD tool, 2022
Michigan energy hardshipU.S. Census Household Pulse Survey

CEO pay and shutoff counts were copied from PDF reports by hand. Change those files only after checking the original document.

To refresh the snapshot:

npm run seed

To refresh one part only, add --only=financial, eia, shutoffs, lead, or pulse.

4. How to run it

You need Node.js. Then, in the project folder:

npm i
npm run dev

Open http://localhost:8080.

The snapshot already in the project is enough. You only run npm run seed when you want newer numbers. The first seed needs the internet. Later runs reuse downloaded files.

CommandWhat it does
npm run devStart the site
npm run seedRebuild the snapshot of checked numbers
npm testTest the upload analysis
npm run typecheckCheck the code for type errors
npm run lintCheck style
npm run buildMake the production build

Everything is TypeScript. There is no Python, no separate server app, and no database.

The folder src/components/ui is a kit of buttons, menus, and dialogs. The real pages barely use it. The charts use only its chart wrapper.

6. How a page gets a number

  1. The page file, for example src/routes/household.tsx, asks for its data before it renders.
  2. That request goes to a function in src/data/measures.ts.
  3. The function reads the snapshot through src/server/measures.ts.
  4. The page draws the result with a chart and a source line.

Code under src/server stays on the server. The browser must not import it. The build fails if it does.

Each stored number is a short list:

[measure, period, grain, dimension, geoId, value]

period is a date like 2024-01-01. grain is month, quarter, or year. dimension is a split such as “homes” or “electric.” geoId is a neighborhood id, or empty when the number is for the whole area.

A year is shown only when every month in that year was reported. A half year is never drawn as if it were a full year.

8. Uploads

On Your data, the browser reads the file first. The server checks the limits again. It does not trust the browser’s row count.

Accepted files: CSV, TSV, Excel (.xlsx), JSON, and one JSON object per line.

  • Up to 10 MB, 20,000 rows, and 60 columns
  • Up to 10 uploads an hour from the same address

The server then describes the columns, writes a trend, a ranking, and a spread, and lines years or places up with the checked DTE numbers. If an API key is set, it can add a short summary. Any sentence that invents a number is thrown away.

Files are saved on the computer running the site, in a folder named .data/uploads. They are not saved in git. Restarting the site clears the hourly limit. A hosted Cloudflare copy of the site has no disk for these files, so uploads work on your machine, not on that host, until a real store is added.

Do not upload names, addresses, phone numbers, or account numbers. Uploads can be opened by anyone who has the link.

The optional summary uses a file named .env. Copy .env.example and set AI_GATEWAY_API_KEY. Leave it empty and the rest of the site still works. AI_MODEL is optional. The default model is openai/gpt-5.4-mini.

9. Before you change something

  • Do not fill in a missing year. Leave the gap.
  • Do not treat an upload as an official figure.
  • Format numbers with src/lib/format.ts and show the source with src/lib/citation.ts.
  • Chart colors come from the --chart- names in src/styles.css. Do not hard-code colors in a component.
  • In the line chart, the axes are passed as a list. Do not wrap them in a React fragment, or the axes vanish.
  • Run npm test, npm run typecheck, and npm run build before you share a change. After a visual change, open the page in the browser.
  • Do not rewrite history that is already on GitHub. No force push.
